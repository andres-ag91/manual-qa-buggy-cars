# Results & Key Takeaways

## Project Results

The Buggy Cars Rating manual QA project produced the following deliverables:

- **26 functional test cases** organized for manual testing.
- **4 exploratory tests** used to investigate application behavior.
- **4 documented defects** describing inconsistencies observed during testing.
- **Automation scripts** developed with AI assistance to support bilingual test documentation and bug report generation.

## Key Findings

The documented defects revealed several types of application behavior that require attention:

- **Input validation:** Differences between password validation feedback in the user interface and the application's registration response.
- **Registration workflow:** Inconsistencies between the enabled state of the Register button and the validation performed by the backend.
- **Navigation:** Unexpected behavior after a successful login.

These findings illustrate why testing should consider not only individual interface elements but also the complete user workflow and the application's response.

## Skills Demonstrated

- Manual functional testing.
- Exploratory testing.
- Test case design and execution.
- Expected-versus-actual result analysis.
- Defect identification and documentation.
- Structured QA documentation.
- Google Sheets and Google Docs.
- Google Apps Script and AI-assisted automation.

## Key Takeaways

This project strengthened my understanding of structured manual testing, reproducible defect reporting, and the importance of consistency between frontend validation and backend behavior.

It also demonstrates how simple automation can reduce repetitive documentation work and support the preparation of QA materials in multiple languages.

## Project Scope

This is a portfolio project based on manual testing of the Buggy Cars Rating application. The results and defect descriptions reflect the observations documented during the project; they should not be interpreted as confirmation that the defects have been fixed or independently verified by the application owner.
